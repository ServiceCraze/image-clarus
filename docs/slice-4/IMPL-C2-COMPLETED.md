## Evidence

- **Failure policy and reporting (E20):** `tests/integration/test_slice4_c2_policies.py` runs default stop-current-image, explicit stop, continue and abort through the actual CLI. Image A fails description with usable persisted downstream text; image B remains eligible. It checks exact per-image stage dispositions, summaries, exit status, source and sidecar bytes, request order and description hashes. The unsupported image suffix enters the provider adapter but fails before HTTP; A4 counts this provider-boundary attempt, not only HTTP calls. `tests/unit/test_c2_failure_request_accounting.py` separately checks real HTTP failure and this local adapter rejection.
- **Rechecks and admission (E10/E18):** `test_slice4_c2_recovery.py` exercises missing prerequisites, valid and invalid JSON backup recovery, and fresh scanning without automatic regeneration of invalid artifacts. `test_slice4_c2_mutations.py` holds real CLI inference after planning and tests nine combinations of changed/deleted/recreated predicted-existing description sidecars and created/deleted/recreated sidecars on an initially known-excluded image. It checks identities, correction counts, dispositions and source bytes. These mutations cover sequential description-stage execution, not every stage or concurrent interleaving. Existing `test_batch_execution.py`, `test_slice4_c1_corrections.py`, and `test_slice4_c1_budget.py` cover additional recovery, routing, correction and exclusion cases.
- **Signals and resume (E13):** `test_slice4_c2_signal_matrix.py` delivers real SIGINT and SIGTERM to CLI processes at discovery/planning entry and during held description/JSON inference with queued images. `test_slice4_c2_signal_resume.py` interrupts a batch and invokes a fresh run, checking reuse of completed outputs and eligibility of unfinished work. `test_c2_signal_safety.py`, `test_xmp_signal_b5.py`, `test_state_accumulation_signals.py` and `test_m3_signals.py` exercise signal and transaction/publication checkpoints; real ExifTool was available for XMP signal tests. The barriers include test instrumentation; they do not simulate interruption inside a filesystem or SQLite syscall.
- **Protected children:** `test_slice4_c2_protected_signals.py` delivers repeated signals, including process-group signals, during admitted description publication at validation/backup/replace checkpoints. `test_slice4_c2_validator_group.py` delivers repeated real POSIX group signals while a real validator child is held during an admitted publication and checks completed publication, retained backup, original bytes, signal-derived exit and child reaping. The test injects schema validation into the description artifact validator to reach that protected boundary; it does not claim the unmodified description validator normally launches a schema child. Before the correction both validator-group cases failed because the child shared the CLI process group. Schema validation, ExifTool execution and ExifTool preflight now start owned children in separate POSIX sessions or Windows process groups. `test_exiftool_process_group.py` checks the actual POSIX ExifTool launch paths; `test_schema_worker.py` also checks Windows launch options by simulation, not Windows runtime.
- **Partial abort and workers (E20):** `test_slice4_c2_worker_failures.py` uses real planning and the concurrent coordinator with synthetic stage callbacks: a stage raises while another image is blocked downstream and another is queued. It checks one terminal fact per selected pair, a preserved completed result, queued not-attempted outcomes, sanitized events and termination. This is an injected callback exception, not an OS-level child failure. Existing concurrent execution and signal tests provide complementary cancellation and accounting evidence.
- **State and independent processes:** `test_c1_state_faults.py` exercises injected optional-state open, read, update and migration faults via CLI, preserves primary outcomes, and checks visible diagnostics and no alternate-store substitution; its lock-contention case uses SQLite. `test_c2_write_safety.py`, `test_m3_concurrency.py`, state storage/migration tests and real-ExifTool `test_c2_xmp_safety.py` exercise independent writers, recovery and state boundaries. These demonstrate the tested valid-output/transaction behavior, not a deterministic winning writer, no lost updates, or an atomic sidecar-plus-state transaction.
